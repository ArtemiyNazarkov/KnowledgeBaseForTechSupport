# Информационная система поддержки эксплуатации АЭС: База знаний «ТОРЭКС»

Централизованная веб-ориентированная база знаний, разработанная для автоматизации процессов технического сопровождения информационной системы поддержки эксплуатации АЭС. Проект спроектирован и реализован для оптимизации сбора инженерного опыта, обмена информацией и сокращения времени обработки инцидентов специалистами 2-й линии службы технической поддержки (СТПП).

Практическая база проекта сформирована на основе производственной деятельности в отделе сопровождения прикладных систем **филиала АО «КОНСИСТ-ОС» «Белоярский» (ИТ-интегратор электроэнергетического дивизиона Госкорпорации «Росатом»)**.

## Безопасность и отказоустойчивость
* **Защита данных:** Исходный код опубликован исключительно в демонстрационных целях для подтверждения квалификации. Локальная база данных SQLite (`ISPETOREKS.db`) внесена в `.gitignore`, а все коммерческие, персональные и чувствительные данные предприятия полностью удалены или заменены на валидные заглушки.
* **Изоляция привилегий:** Проектом предусмотрено жесткое разграничение ролей доступа (Администратор/Пользователь СТПП). Для обеспечения безопасности инфраструктуры АЭС конечные пользователи работают без предоставления им административных привилегий в ОС.
* **Защита сессий:** Валидация логинов и паролей выполняется на уровне серверных форм Flask-WTF. Пароли хранятся в БД в виде криптографических хэшей (`werkzeug.security`). Сессии пользователей неперманентны и уничтожаются вместе с удалением сессионных Cookie при закрытии браузера.
* **Отказоустойчивость:** Время восстановления системы после нефатальных инфраструктурных сбоев (например, перебоев электропитания) не превышает 30 минут при сохранении целостности данных благодаря транзакционной модели СУБД.

## Системные требования и совместимость
* **Импортозамещение:** Программный продукт полностью адаптирован и корректно функционирует в среде отечественной защищенной операционной системы **Astra Linux** (а также на Windows и macOS).
* **Среда выполнения:** Python 3.9+
* **Ресурсоемкость:** Приложение оптимизировано под жесткие инфраструктурные ограничения и стабильно работает на минимальных аппаратных мощностях (процессор от 1 ГГц, от 1 ГБ RAM, от 200 МБ свободного места на диске).

## Технологический стек
* **Backend:** Python 3.x, Flask, Flask-SQLAlchemy (ORM), Flask-Login (управление сессиями), Flask-WTF & WTForms (валидация данных и защита от спама).
* **Frontend:** HTML5, CSS3 (Bootstrap-верстка в корпоративных тонах), JavaScript (AJAX-запросы для динамических интерфейсов, Quill rich-text editor).
* **Архитектура данных:** Реляционная СУБД SQLite. Реализована объектно-реляционная модель из 12 таблиц. Спроектирована иерархическая структура связей `Система -> Модуль -> Приложение`.

## Ключевой функционал
1. **Динамическая фильтрация (AJAX):** При создании или редактировании инцидентов (заявок) списки систем, модулей и приложений последовательно фильтруются «на лету» без перезагрузки страницы на основе связанных полей (`ModuleApplications`).
2. **Контекстно-зависимый поиск:** Интегрирован гибкий поисковый движок по базе инцидентов, работающий по принципу поиска подстроки вне зависимости от регистра букв во всех полях данных (поиск по описанию, решению, автору, дате или названию узла).
3. **Rich Text & Media:** Редакторы описания проблем и решений поддерживают сквозную стилизацию текста (заголовки, списки, ссылки), а также прямую вставку скриншотов и изображений из буфера обмена (`Ctrl+V`).
4. **Встроенные инженерные справочники:**
   * Реестр оттестированных SQL-запросов и скриптов для быстрой выгрузки данных или проведения типовых выборок из смежных баз.
   * Валидируемый загрузчик/хранилище файлов и шаблонов для Loader'а (с жесткой проверкой расширений электронных таблиц `.xls`, `.xlsx`, `.ods`).
   * Справочник полезных веб-ссылок, контактов и нормативных документов (`.pdf`, `.doc`, `.docx`).
   * Панель быстрого копирования Конфигурационных Единиц (КЕ) в буфер обмена для ускорения закрытия заявок во внешних Service Desk системах.

## Структура репозитория
* `app.py` — центральный модуль приложения: маршрутизация (Routes), бизнес-логика, описание моделей базы данных SQLAlchemy, AJAX-контроллеры.
* `forms.py` — декларативное описание веб-форм, кастомные валидаторы уникальности записей и проверки структуры данных.
* `setup.py` & `requirements.txt` — конфигурация пакета и манифест зависимостей для сборки изолированного виртуального окружения.
* `templates/` — иерархия Jinja2-шаблонов веб-страниц приложения.
* `static/` — клиентские статические ресурсы (корпоративные стили CSS, логика JS, иконки).

## Инструкция по локальному развертыванию

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/ArtemiyNazarkov/KnowledgeBaseForTechSupport
   cd KnowledgeBaseForTechSupport
   ```

2. **Инициализируйте изолированное виртуальное окружение:**
   ```bash
   python -m venv venv
   # Для Windows:
   venv\Scripts\activate
   # Для Linux / macOS:
   source venv/bin/activate
   ```

3. **Установите программные зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Запустите сервер веб-приложения:**
   ```bash
   python app.py
   ```
   *База данных SQLite спроектируется и сгенерируется в каталоге `instance/` автоматически при первом старте сервера.*

5. **Откройте систему в браузере:**
   ```text
   http://127.0.0.1:5454
   ```
